# Тесты для labwork3 (песчаная куча)

Black-box тесты: запускают **ваш собранный бинарник** с разными аргументами и проверяют
код возврата и получившиеся BMP. В ваш проект ничего добавлять не нужно, от структуры
вашего кода тесты не зависят.

## Запуск

```bash
# 1. соберите свою лабу как обычно
cmake -S labwork3-<you> -B labwork3-<you>/build && cmake --build labwork3-<you>/build

# 2. соберите тесты, указав путь к своему бинарнику (лучше абсолютный)
git clone <этот репозиторий> labwork3-sandpile-tests
cd labwork3-sandpile-tests
cmake -B build -DLABWORK3_BIN=$(realpath ../labwork3-<you>/build/bin/labwork3)
cmake --build build

# 3. запуск
ctest --test-dir build -j8 --output-on-failure          # все
ctest --test-dir build -j8 --output-on-failure -R Spec  # только то, что есть в условии
```

На Windows путь к бинарнику будет `...\labwork3.exe`. Бинарник можно подменить без
пересборки: `LABWORK3_BIN=/path/to/labwork3 ctest --test-dir build`.

Большие примеры (fractal и т.п.) в Debug-сборке считаются заметно дольше. Если тесты
идут медленно, соберите лабу с `-DCMAKE_BUILD_TYPE=Release`.

## Что проверяется

**`Spec*`: только то, что прямо написано в условии**
- флаги `-i/-o/-m/-f` и `--input/--output/--max-iter/--freq`, ошибки (неизвестный флаг,
  нет обязательного, отрицательное или нецелое значение): ненулевой код и **без падения**;
- создание директории `-o`, в том числе вложенной;
- BMP: ≤ 4 бита на пиксель, размер = размеру сетки, цвета 0/1/2/3/>3;
- сохранение: `--freq 0`, кратные `freq` плюс последнее, без повторного сохранения
  последнего, `--max-iter 0` сохраняет начальное состояние;
- правила модели: первая итерация вручную, правило 3 (новый песок ждёт следующей итерации),
  узор из 16 песчинок;
- таблица из README: размер и **точное** число итераций для fractal / twin-piles /
  four-piles / square, симметрия, сохранение песка.

**`Extra*`: условие этого явно не требует, но так разумно**
- `--input=file` (форма с `=`), несуществующий входной файл, `-o` указывает на файл;
- одинаковые координаты суммируются, CRLF и пустые строки допускаются;
- битые TSV (буквы, дроби, лишние/недостающие столбцы, отрицательный песок,
  координата вне `int16_t`, переполнение `uint64_t`) отвергаются.

Если `Extra` падает, это не обязательно ошибка: возможно, у вас другое решение.

## Чего тесты НЕ предполагают (в условии этого нет)

- **Имена файлов** могут быть любыми с расширением `.bmp`. Порядок картинок определяется по
  последнему числу в имени (`5.bmp`, `iter_000010.bmp`, `out-12.bmp` подходят).
- **Точные RGB**: цвета сравниваются нестрого, например `(0,128,0)` и `(0,255,0)` оба
  считаются зелёными. Чёрный — почти `(0,0,0)`, белый — почти `(255,255,255)`.
- **Порядок цветов в палитре** может быть любым: цвет берётся из таблицы цветов BMP.
- **Направление оси Y**: принимается и картинка, отражённая по вертикали.
- **Вывод в stdout/stderr** не проверяется. Число итераций вычисляется через `--freq`
  (при `-f N` одна картинка, при `-f N-1` две, значит итераций ровно N).

Нашли ошибку в тестах или спорный момент — пишите.
